The words this map uses

Six words, then everything below makes sense.

Catalog One line per thing worth naming in the repo — its kind, whether anything reads it, and whether it has a card. The full list, no explanations. Sits in §1 of examples.md · rendered below
Card A write-up of one thing: what it is, why it's built that way, what else changes if you touch it, and what looks like it changes but doesn't. The catalog names everything; a card explains one thing. Sits in §2–§4 of examples.md · rendered below
Noun card A card about a thing — a script, a file, a setting. This map has three: caption.py, 01-transcript.json, tools/measure_audio.py. §2 of examples.md
Ghost unused, looks used Something nothing reads, while everything around it says it's in charge. The dangerous kind: you change it expecting an effect, or you trust it and delete the code that does the real work. Here: caption_motion and twelve settings beside it. §3 of examples.md · red rows in the catalog
Leftover unused Something nothing reads, and nothing pretends otherwise. Honest clutter — safe to ignore, cheap to delete. Here: reference/source-specs/, tools/render_smoke_test.py (never run), 04-proposed-words.md (never yet written). Amber rows in the catalog
Change card A card about an action instead of a thing: one change you'd actually make, followed through everything it hits — and everything it looks like it hits but doesn't. This map has one: fixing a misheard word. §4 of examples.md

The closed list of the eight kinds a catalog row can be, the reading order, and the words that mean two things live in reference/ next to examples.md — all three rendered at the bottom of this page.

The walk — where to start with no question

If you have a question, don't walk: find the row in the catalog, open its one card, stop. This section is for arriving with no question yet.

The front door is caption.py — one command, one video, six steps in a fixed order at caption.py:45-52. Everything else is a step in that run, a file the run passes along, a value a step reads, or prose about what a step may not do.

caption.py                       the run
  → 01_ingest                    the video is read, then transcribed
      01-video.md                path, length, frame rate — hand-editable
      01-transcript.json         the words and their timings — the file you edit
      01-transcript-raw.json     the same, written once, never touched again
  → 01b_calibrate                the audio is evened out
  → 02_assemble                  words become subtitle cards, plus an .srt
  → 03_render                    the subtitles are burned on

off to the side:  04_learn      run by hand after you fix a word
underneath:       _config/edit-defaults.yaml — every stage reads it

2 · The noun cards

Each card answers the same four questions. The last one — what looks like it changes and doesn't — is the reason the card exists.

command

caption.py — the one command that runs everything

What it is

Runs six steps over one video, in a fixed order, at :45-52. Everything else in the repo is one of those steps, a file passed between them, a value a step reads, or a rule about what a step may not do.

Why it's built this way

--redo lets you fix a misheard word without transcribing again — transcribing again would just bring back the same wrong word. So it re-runs the list from step 3 on. But the 3 is typed by hand at :66; the comment at :54-65 shows someone moved it from 2 to 3 when the audio step was added.

What else changes

The order of a run — :45-52 is the only place it lives. And --redo, in a way you wouldn't expect: add a step above position 3 and the 3 stays put, so the rebuild starts in the wrong place with no warning. Also the after-edit checks — tools/sync.py:32 names this file by name.

What looks like it changes and doesn't

CONTEXT.md. It holds the diagram of which stage runs when, and CLAUDE.md:57-61 sends you there before any change — but nothing opens it. Change the steps and the diagram goes quietly wrong until someone notices.

handover file

01-transcript.json — the words, and the file you edit

What it is

Every word said, with start and end times, plus the video's path, length, and frame rate. Written by transcribe.py:136 to output/runs/[slug]/. When a word comes out wrong, this is the file you fix.

Why it's built this way

Two non-obvious things. It's written twice: 01-transcript-raw.json is a copy made once (transcribe.py:140-147) and never touched again — not a backup, but the only record of what was originally heard, which is how learn_words.py spots your corrections. And its "video" line is overwritten mid-run to point at the evened-out audio copy (calibrate_audio.py:195) — which is why the audio stage reads 01-video.md instead (calibrate_audio.py:12-17).

What else changes

02-caption-cards.json and 02-captions.srt, both rebuilt from it. 03-remotion-props.json and the finished video — the render takes length, frame rate, and path from here instead of reopening the video (render_captions.py:44-52). And the audio stage, since sound levels are measured over speech.

What looks like it changes and doesn't

01-transcript-raw.json. Same folder, almost the same name, same shape — the obvious file to reach for, and the wrong one. Overwrite it and every correction stops looking like a correction: nothing breaks out loud, the word list just quietly stops growing (governance.md, rule 3).

shared part

tools/measure_audio.py — needed by every run, filed under “not part of a run”

What it is

Measures the sound: loudness moment by moment, and where someone is speaking. Sits in tools/, runs on every video, used at measure.py:41.

Why it's built this way

First written to produce the numbers in reference/source-specs/audio-measurements.md. The audio stage reused it rather than measuring the same thing a second way (measure.py:18-23) — two versions of one measurement would drift apart. Side effect: the repo's own description of itself is wrong here. CLAUDE.md:94-95 skips this file; BUILD-NOTES.md:122 says of tools/, “None of them is part of a run.”

What else changes

Every run — break it and a run stops at the audio step. Also audio-measurements.md, since every number in it came from this script.

What looks like it changes and doesn't

The checks in tools/sync.py. It watches stages, _config, and memory, plus two files by name (:31-33) — not tools/. The one file in tools/ a run depends on is the one file the check was never told about.

3 · The ghost

ghost — setting

caption_motion — a setting nothing reads

What it is

caption_motion: none at edit-defaults.yaml:33 means subtitles don't pop, light up word by word, or type themselves on. That's genuinely how they behave — but nothing reads the setting to make it happen. It's one of thirteen settings in that file read by nothing:

gap_between_cards_s :31 · lead_in_s :32 · caption_motion :33 · prefer_fewest_cards :57 · preserve_quotes :61 · anchor_semantics :133 · allow_serif :184 · hierarchy_via :185 · background_box :195 · subtitles_topmost :197 · render.resolution :486 · render.single_export_serves :487 · max_words_per_card :507

Twelve sit under a heading called rules:, which says at :9: “rules: enforced. A violation is a bug.”

Why it's built this way

The file was built by hand from two written specs, and every value they mentioned got copied in so nothing was lost. Good instinct — but it left values that record a decision in a file meant to hold what's enforced. The behavior lives elsewhere:

SettingWhere the behavior actually is
caption_motionCaptionedVideo.tsx:14-19 — no interpolate() call anywhere in the file, so nothing can move unless someone adds it
subtitles_topmostsame file, :23 and :57-94 — subtitles are drawn last, which puts them on top
background_boxsame file, :83 — background: "none" is written into the code
gap_between_cards_ssubtitles are built end to end; :27-29 depends on it
anchor_semanticsrender_captions.py:160 and CaptionedVideo.tsx:64 center the block; the setting describes what they do
render.resolutiona duplicate of geometry.canvas at :112, which is read, at render_captions.py:203

render.resolution is the clearest case: set it to any size, the video still comes out 1080×1920. This setting was called animation until 2026-08-24, when “delete everything about animation” nearly took it out along with an unrelated project of the same name — see the collisions below.

What else changes

Nothing. Change it, delete it, flip it — no run behaves differently. That's the finding, not a footnote. What it does affect is the next person, who'll believe the setting controls the behavior and may delete the code that actually does.

What looks like it changes and doesn't

CaptionedVideo.tsx — the file that would animate subtitles if anything did; the values handed to it (render_captions.py:210-233) never include this setting. Also the words_per_card pair at :506-507: only the upper one is read, and only to print a count (chunk_captions.py:385). Neither caps anything — a 2.5-second limit already stops a subtitle at about eight words (:504-505).

Unconfirmed, found 2026-08-26: allow_orphan_cards at edit-defaults.yaml:42 looks like a fourteenth — it sits under rules:, and no code reads the key. Not yet in the map; check it before trusting either count.

4 · The change card

change card

“A word came out wrong. I fixed it in 01-transcript.json.”

What it hits
What changesWhy
02-caption-cards.jsonrebuilt from the corrected words
02-captions.srtrewritten from those
03-remotion-props.jsonrebuilt, carrying the new text
the finished .mp4rendered again — the slow part
memory/caption-fixes.mdonly if you then run learn_words.py, which no run calls
What looks like it changes and doesn't

The evened-out audio in output/audio/[slug]/. Everyone reaches for it, for a good reason: the transcript's own "video" line points straight at it. It isn't touched — caption.py:66 starts the rebuild at step 3, below the audio step; fixing a spelling can't change the audio, and re-running that slow step would produce an identical file (caption.py:58-65). Same for 01-transcript-raw.json, per its card above.

The eight kinds a row can be

The list is closed: a card names one of these, never a ninth invented on the spot. Each kind answers “what else changes?” differently — that's what makes it a kind and not a label. (reference/card-types.md)

KindWhat it isWhat changing one moves
commandThe one thing that decides what runs and in what order: caption.py. The only member — the only thing that chooses the work.What runs, in what order, and which steps a rebuild skips.
stageA numbered folder under stages/: a CONTEXT.md and its scripts. Takes named files, writes named files.The files either side of it, and the step list at caption.py:45-52.
handover fileA file in output/runs/[slug]/ one stage writes and another reads — or that leaves as something you keep. Most are also where a person edits by hand.Every stage after the one that writes it.
settingA named value in _config/, or an override in memory/preferences.md.Whatever reads it — or nothing at all, which is worth checking before you trust one.
written ruleWriting that binds behaviour and that no code opens: CLAUDE.md, governance.md, the CONTEXT.mds, terminology.md.Nothing runs differently. People and models behave differently — slower to notice, harder to undo.
shared partCode more than one stage uses and no stage owns: pipeline_lib.py, tools/measure_audio.py, remotion/.Every stage that reaches for it — and how far that reaches isn't visible from its folder.
checkSomething that runs by itself and either stops you or reports: sync.py, the fixture checks, the after-edit hook.What is allowed to break quietly. Weakening one changes nothing today.
running tallyA file that builds up across runs: caption-fixes.md, boundary-tally.md.Nothing. No run reads one to decide anything. Delete one and the count restarts — that's the whole effect.

The two pairs that get confused. A setting and a running tally both persist between runs but are opposites: a setting is read to decide something, a tally is written to remember something — find the line that reads it. A written rule and a check both stop bad changes: one by being read, one by failing. Only the check works on a reader who never opened it.
